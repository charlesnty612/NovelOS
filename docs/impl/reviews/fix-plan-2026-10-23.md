## Task 3：备份链——默认加密、密文自检、密钥缺失报错、恢复工具（D-2/D-3/D-4/D-5）

**一句话**：备份「有写无读」——写的时候默认明文且从不验证密文可解，读的时候没有工具、带 `-wal` 残留会静默失效、解密失败还会把活库改坏。

### 背景与证据（子代理实跑 + Lead 复核结论）

- 真实 openssl 往返**实测跑通**（49 表逐表 sha256 全等、`integrity_check=ok` 两侧、CJK/emoji/二进制逐字节一致）
  ⇒ **加密实现本身没问题**，问题在**默认策略**与**恢复侧**。
- `scripts/backup_db.py:217-219`：`"--encrypt"` 是 `action="store_true"` ⇒ **默认关**；
  `:293-294` else 分支 `shutil.move(str(plain), str(dest))` ⇒ **默认落明文**；
  `:219` help 写「**推荐**」的那个 flag 恰恰是 opt-in 的。
- `:288-291`：加密后 `plain.unlink(missing_ok=True)` 删掉唯一明文，而
  `[校验] integrity_check=ok（在加密前的明文副本上做的）` ⇒ **加密后的密文从未被验证可解**。
- `ensure_key_file` 在密钥文件缺失时**静默生成新密钥**（实测 key 前 8 位 `ab1d0551`→`c53b90f5`，
  用新 key 解旧密文 exit 1 `bad decrypt`）⇒ 旧备份**永久不可恢复**。
- 恢复侧实测（子代理）：
