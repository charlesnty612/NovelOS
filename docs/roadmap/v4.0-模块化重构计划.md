# V4.0 模块化评估与重构计划（2026-09-13，全面审查输入）

> 来源：V3.9 全量检修 R1/R5 的技术债度量与结构发现 + 本轮全部批次实施经验。
> 结论先行：**本项目已是模块化设计**（分层清晰、门面模式、依赖方向有测试看守、
> 新资源类型有落地范式）——不需要推倒重来；要做的是**消解 4 个存量热点 + 2 类
> 结构性负债**。重构纪律已并入 AGENTS.md §二（新增模块 ≤1500 行硬顶）。

## 一、模块化现状评估（判据与实证）

| 判据 | 判定 | 实证 |
|------|------|------|
| 分层与依赖方向 | ✅ 健康 | core/domain/workflows/apps 四层；`core 不得 import workflows` 有专门测试看守（test_no_core_to_workflows_dep） |
| 巨型文件治理 | ⚠️ 热点位移 | builders 3678→7 模块（09-06）但 builders_common 回涨到 **2104**；chapter_commit 2262→5 模块后最大 955（**健康线样本**） |
| 门面模式 | ⚠️ 有意负债待收口 | builders 门面 116 导出名 68 个（59%）外部零引用（R1 m8） |
| 新资源范式 | ✅ 可复用 | genre_pack（自有表/schema 版本线/CRUD/绑定/注入/缓存键指纹）即为模板 |
| 脚手架残留 | ⚠️ 12 空包 | packages/agents 六角色空包 + domain 三空包等（R1 m9，Sprint 0 遗留） |

## 三、结构性负债 2 类

1. **门面 `__all__` 膨胀**：随拆分 #1 一起收缩；规则=「导出名必须有消费方或测试」（AGENTS.md §二.1 已载）。
2. **空包与死定义清理**（R1 m7/m9）：12 个 Sprint 0 空包（planner 等）加「未实现骨架」注记或删除；5 个真 0 引用 def（`_provider_default_base_url`/`_last_n_chars`/`_hits`/`_apply_inverse_cleanup_to_state`/`_build_inverse_delta`/`parse_snapshot`/`_delete_chapters_for_volume`）逐个裁决（删或接线，`_delete_chapters_for_volume` 疑似失联接线需确认意图）。

## 四、明确不做（证据化裁决）

- **引擎 DAG 化/条件边**：节点内循环已覆盖需求（condense 先例），迁移收益不抵成本（R10 已裁）。
- **状态机显式枚举化**（R6）：四端联动面大收益小，维持异常+字符串现状，已登记。
- **前端全面组件库化**：自用工具，随热点 #3/#4 自然演进即可。

## 五、排期

本计划不占用当前检修收尾；建议作为 **V4.0 首个开发批次**（预计 2~3 天：#1 一天、#2 半天、#3/#4 半天、负债清理半天），届时按文件互斥分组并行实施 + 等价性审查。
