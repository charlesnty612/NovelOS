# V3.7~V3.9 迭代计划（2026-08-27 制定）

> 依据：V3.6.0 实测数据（docs/roadmap/v3.6-单章提速与竞品对标.md）+ 竞品对标
> （oh-story / determinFlow / bishu-novel）+ 定向侦察报告（target_word_count 链路 /
> prose_chars 口径 / review 校验器 / critic 开关 / writer 正文流 / DB 残留）。
> 原则：**闭环无候选项**——每一项要么实施落地，要么经实验/论证后给出不做决策并留痕；
> 禁止"以后再说"。

## 现状基线（V3.6.0 @ d351c97）

- 单章全链：658~866s（ch065/066/067），无挂起；本地环节 <15s；瓶颈 = plan+write 两段
  LLM 服务端解码（550~580s，其中 completion tokens 约 95% 为思考串）。
- 前缀缓存：plan 二次装配命中 94%，observer 一腿 48%，summarizer 100%；writer 仅 1%
  （其 payload 前段 chapter/director_plan 全动态，属预期，见 F 项裁决）。
- 质量：prose_chars 2397 在带内；quality_overall 77~89 波动（critic sample 模式下多为
  静态分）；review 多数章节因 sample 跳过走 0.1~0.2s 快路径。

## 版本规划

### V3.7「字数带硬约束与口径统一」

目标：把 writer 正文长度从"静态百分比希望"变成"payload 显式带 + 全链路统一度量 +
校验器可见告警"，为后续降低思考预算打地基。

| # | 事项 | 落地物 |
|---|------|--------|
| A1 | 权威字数模块 | `packages/core/quality/wordcount.py`：`visible_chars`（去空白）、`word_band(target)`、`classify_prose_length` |
| A2 | payload 注入字数带 | `build_writer_input` 的 `chapter` 子对象**末尾**追加 `word_band:{low,high,floor}`（保持在 chapter_id 后追加，零破坏既有前缀缓存键序） |
| A3 | 口径统一 | signing_check._count_chars / arc.service / m1_long_run._latest_prose_chars 收敛引用 wordcount.visible_chars；chapter_review `_basic_checks_node` 由 `len(prose)` 改 visible_chars |
| A4 | review 校验升格 | 字数检查产出 rule_id=`W-LEN-DEVIATION`：>±15% warning（沿用）；>±30% 进 error 列表（报告型：随 pause payload 展示给作者，不做 enforce 阻断）；文案注明 target/band 实测值 |
| A5 | m1 观测强化 | progress/metrics 增加 `word_status`(in_band/under/over) 与 `deviation_pct` |
| A6 | 实测 | ch068 全链：验证 write completion tokens 是否较 ch067（42k）下降、字数在带率 |

验收：707+ 新增测试全绿；ch068 COMMITTED 且 word_status=in_band 或偏离 ≤±30%；
cached_tokens 无回归。

### V3.8「writer 生成形态取证与形态决策」

风险前提：MiniMax 思考 token 可能是 per-call 固定开销——若拆 3 段每段仍烧
30~40k 思考 token，分段反而变慢。**先用一次性直调实验定方向，再决定实现**。

| # | 事项 | 内容 |
|---|------|------|
| B1 | 分段可行性实验 | **已完成（2026-08-27，直调 MiniMax）**：整章 1692tok/24s vs 两段合计 2484tok/34s——ratio_tok=1.47、ratio_time=1.39，远超 0.85 判据 → **分段写作否决**。修正生产模型名（MiniMax-M3）后复测两点：① 输入规模不是思考 token 的单调诱因（小上下文 comp=20588/out_chars=51736 vs 大上下文 comp=14852/out_chars=37384）；② 裸调模型会大幅无视字数纪律（1800 字目标写出 5 万字符）——生产产出的有效约束来自 NovelOS 装配层与校验层，V3.7 把字数带做进装配侧是正确层次 |
| B2a | ~~分段写作实施~~ | **不实施**（B1 判据否决：多一次调用=多一份固定开销） |
| B2b | 否决后的替代动作 | 已落地两项取证：① B1 实验数据（上）；② **provider 原始响应采样开关** `NOVELOS_DEBUG_PROVIDER_DUMP_DIR`（默认关，保留最新 10 个文件，单文件 2MB 截断）——用 ch068 真实链路量化 writer completion 中思考串 vs JSON 正文的构成，把"42k completion 去哪了"从猜测变成证据 |
| B3 | 实测与定论 | ch068 全链计时 + word_status（与 V3.7 A6 合并验证）+ 采样文件分析；分析结论回填本表并在 CHANGELOG V3.8 记录后续形态判断（若证据显示提示词级可裁剪则给出一项小改并实测，否则记录不做依据闭环本版） |
