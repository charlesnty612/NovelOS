# 专项题材库：评估与落地计划（2026-09-13）

> 需求：用户提出融入专项题材库，以「男主快穿文」为第一个题材（番茄当前热门题材）。
> 硬约束：**软件工具层与内容层分离**（沿用 2026-09-11 三仓分离裁决）。
> 本文档 = 评估结论 + 落地计划。评估表摘要已登记为 roadmap 评估表 R16/R17。

## 一、需求定义

「题材库」= 跨作品聚合的**题材公约资产**：某题材（如男主快穿）的结构模板、爽点分类法、
人设 archetype、位面/世界观库、桥段映射、文风与平台规则。它与现有 ReferenceCanon 的
差别：canon 是**单部参照作品的拆解产物**（描述性），题材库是**多部爆款+策展的规定性公约**
（规定性），消费范围为项目级常驻。

## 三、对既有机制的批判性评估（初判已推翻，留痕）

> 初判（已被推翻）：「canon 的 payoff_list/emotion_curve/protagonist 就是为此建的，不需要新机制」。
> 推翻理由逐条如下——**本项目规矩：先验判断被推翻必须记录，以免重蹈**。

| 既有机制 | 初判 | 复核结论 | 关键证据 |
|---------|------|---------|---------|
| payoff_list（scene_planner 消费） | 直接复用 | ❌ 容器错位 | 它是单书节拍清单（≤30 条，描述性）；题材库要的是规定性类型分类法（20~40 类型 × {场景, 密度上限, 同型间隔, 疲劳管理}） |
| emotion_curve | 直接复用 | ❌ 记录 vs 模板 | canon 曲线是拆出来的既有曲线；题材库要目标曲线模板 + **逐章核销**，现有消费是「喂参考文本给 LLM」，无任何结构化核销 |
| protagonist schema | 直接复用 | ❌ 实例 vs 类型 | 单一主角卡（identity/tags/core_drive/foils）；题材库要 archetype 枚举 + 选择指引 |
| active_canon 机制 | 复用绑定 | ⚠️ 需改造 | 项目级唯一 slot 是互斥单选；「题材包常驻 + 参照书叠加」双资源并存需要双 slot |
| 注入管道（`_reference_canon_excerpt` consumer 模式） | — | ✅ 复用 | 新资源类型走同一注入管道，这是真价值 |
| 拆书工作流 | — | ✅ 复用（改聚合目标） | 题材包素材来源；聚合产物不共用 canon schema |
| canon→风格卡确定性联动 | — | ✅ 移植 | 题材包→项目预设照抄 to-style-sample 零 LLM 模板法 |
| signing_check 黄金三章 | — | ✅ 参数化扩展 | 题材包做规则覆盖，机制不动 |

## 四、修正版架构裁决

1. **新建独立资源 `genre_pack`**：自有表、自有 schema 版本线、自有校验器。不给 canon
   加 `genre_sections`（避免拆书链路与题材链路耦合：G-sim/schema 校验/聚合器契约互相掣肘）。
2. **双 slot**：`genre_pack_id`（项目常驻）与 `reference_canon_id`（叠加）并存。
3. **核销层为第一公民**：爽点类型逐章核销、配比摊到 scene、偏差进 quality 报告——
   与 R2（内容配比）同体，是 InkOS #260 式痛点（LLM 不持久遵守内容配比指令）的正解：
   **规划期硬约束 + 逐章核销**，而非 writer 自觉 + 事后审计。
4. **分层**：
   - 内容层（NovelOS-Content/genres/<题材>/）：10 维资产，含禁忌清单与维护公约
   - 软件层（NovelOS）：机制 only——资源 CRUD、注入管道、核销层、同步命令
   - **红线**：审核禁忌/题材内容只进内容仓；prompt 源文件（prompts/）属软件仓，
     题材 rubric 属内容仓，运行时读取，不入 prompts/

## 六、验收标准

- P0：题材包 10 维文件齐备；至少 1 本爆款拆书产出回填 ≥3 维；试产章节（人工评审对照
  REVIEW-CHECKLIST）在爽点密度/章末钩子上较无题材包对照组有可感知提升（留评审记录）。
- P1：migration 幂等可回滚；双 slot 并存时 builder 注入互不污染（缓存键含 genre_pack_id）；
  核销层 report-only 字段进 quality 报告；新增测试 ≥40 用例；ruff 0。
- 每批次：CHANGELOG 留痕；题材内容不入软件仓（git 层面验证：软件仓 diff 无题材正文）。

## 七、风险与开放问题

1. **平台规则时效**：fanqie.json 标注生效日期；题材包 profile 标热度周期；季度复盘写进维护公约。
2. **版权边界**：拆书产出=结构化笔记非原文（沿用 G-sim 13 字重叠拦截与「禁原文片段」约束）；对标书单只存书目元数据。
3. **审核红线**：只进内容仓，软件层只提供「禁忌检查」机制；prompt 内引用不入库 prompts/。
4. **热度漂移**：机制按可插拔题材包设计，不为快穿特化任何硬逻辑；第二个题材包接入成本是内容工作而非代码工作。
