# M2 验证报告：上限能力干预效果

- 验证方式：在 M1 长跑同一项目上连续生成新章，用 LLM judge 探针（`scripts/m2_judge.py`）与规则引擎双轨对比。
- 干预清单：director Rules 10-11（[payoff] 前置 + 字数纪律）、Rules 12-14（叙事推进纪律/停滞强制升级/交互密度下限）；writer Rules 13-17（反碎片化/字数纪律/对话占比/payoff 可感知兑现）；驱动脚本 TARGET_WORD_COUNT 700→1800。
- 数据源：`docs/evaluation/m2-judge/judge_results.json`、`data/m1_run/chapters/ch0NN.json`。

## 遗留问题（转入 M3）

1. **ch056 顽固阻塞**：observer 对第 56 章反复超时/FK 约束失败（快照已 >110KB）。FK 失败暴露 validator 不校验引用实体存在性的缺口。→ M3 做 observer 输入瘦身（max_changes 上限、快照分代裁剪）+ validator 引用存在性校验。
2. **style 子分未随 judge 改善而上升**：规则分与 LLM judge 的文风判定口径不一致，印证 deviation #11——需要把 LLM judge 正式接入评分语义（当前 judge 是旁路探针）。
3. **叙事仍以"量桩"为主线**：干预让章节有了交互与新元素，但主线惯性仍在；长跑级故事弧光管理（多卷节奏规划）超出 prompt 层能力，属于 M4 写作现场/规划工具范畴。
